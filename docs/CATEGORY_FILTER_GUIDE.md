# Как добавить фильтр по категории

Пошаговая инструкция для текущего приложения «Мои задачи».

Цель: выбирать одновременно статус и категорию. Например, «Активные» + «Планерка» или «Выполненные» + «Планерка». Поиск и сортировка при этом продолжают работать.

Это инструкция для самостоятельной реализации. Код приложения при создании этого файла не изменялся. Делай шаги по порядку: после первых двух готова логика, после следующих двух — интерфейс.

## 1. Как будет работать новый фильтр

На экране появятся две независимые группы кнопок:

```text
Статус
[Все] [Активные] [Выполненные]

Категория
[Все категории] [Работа] [Учеба] [Планерка] [Дом]
```

В каждой группе выбирается один вариант. Выбор категории не должен сбрасывать статус, а выбор статуса — категорию.

| Статус | Категория | Что показываем |
|---|---|---|
| Все | Все категории | Все задачи, подходящие под поиск |
| Активные | Планерка | Невыполненные задачи категории «Планерка» |
| Выполненные | Планерка | Выполненные задачи категории «Планерка» |
| Все | Планерка | Все задачи категории «Планерка» |
| Активные | Все категории | Активные задачи любой категории |

Все условия работают вместе: **поиск + статус + категория**. После отбора применяется существующая сортировка.

Не нужно создавать отдельные варианты «Активные планерки» и «Выполненные планерки». Достаточно двух независимых значений в состоянии.

## 2. Какие файлы понадобятся

| Файл | Действие | Ответственность |
|---|---|---|
| `lib/state/todo_state.dart` | Изменить | Хранить выбор категории и отбирать задачи |
| `lib/widgets/category_filter.dart` | Создать | Показывать кнопки категорий |
| `lib/todoscreen.dart` | Изменить | Связать новые кнопки с состоянием |
| `lib/models/task_options.dart` | Использовать без изменений | Брать существующие названия категорий |

Модель `Task` уже содержит `category`, поэтому добавлять в задачу новое поле не нужно. Хранилище и форма тоже остаются прежними: фильтр лишь решает, какие задачи показать.

## Шаг 1. Сохрани выбранную категорию в состоянии

Открой `lib/state/todo_state.dart`.

В начале класса `TodoState` найди поля `search`, `filter`, `sort`. Добавь рядом поле `category`:

```dart
final TaskRepo repo = TaskRepo();
String search = '';
String filter = 'Все';
String category = 'Все категории';
String sort = 'Сначала новые';
```

Добавляется только одна новая строка, остальные уже существуют.

Теперь:

- `filter` хранит статус: «Все», «Активные» или «Выполненные».
- `category` хранит категорию для просмотра либо «Все категории».
- `task.category` по-прежнему хранит категорию конкретной задачи.

Например, `state.category = 'Планерка'` означает «покажи планерки», а `task.category = 'Планерка'` означает «эта задача относится к планеркам». Выбор фильтра не меняет категорию задач.

**Почему начальное значение «Все категории»?** Чтобы при открытии приложения новый фильтр ничего не скрывал.

Не добавляй «Все категории» в общий список `categories`: это режим просмотра, а не категория, которую можно назначить задаче в форме.

## Шаг 2. Добавь проверку категории в visible

В этом же файле найди getter `visible`.

Перед строкой `list.add(task);` добавь:

```dart
if (category != 'Все категории' && task.category != category) {
  continue;
}
```

Для сверки ниже приведён **весь getter после изменения**. Можно заменить существующий getter этим блоком. Не добавляй второй `visible` и не заменяй весь класс: методы `compare`, `add`, `edit`, `toggle`, `remove` должны остаться.

```dart
List<Task> get visible {
  final List<Task> list = [];
  final text = search.trim().toLowerCase();

  for (final task in tasks) {
    if (!task.title.toLowerCase().contains(text)) {
      continue;
    }
    if (filter == 'Активные' && task.done) {
      continue;
    }
    if (filter == 'Выполненные' && !task.done) {
      continue;
    }
    if (category != 'Все категории' && task.category != category) {
      continue;
    }
    list.add(task);
  }

  list.sort(compare);
  return list;
}
```

### Разбор нового условия

```dart
category != 'Все категории'
```

Выбрана конкретная категория, значит нужно проверять принадлежность задачи.

```dart
task.category != category
```

Категория задачи не совпадает с выбранной.

`&&` означает «и»: пропускаем задачу, только когда обе части истинны. `continue` переходит к следующей задаче в цикле.

Пример: выбрана «Планерка», а у задачи категория «Дом». Обе части истинны — задача не попадёт в список для отображения.

Если выбраны «Все категории», первая часть ложна и это условие никого не исключает.

**Проверь расположение:** новая проверка должна стоять до `list.add(task)`. Иначе неподходящая задача уже окажется в результате.

## Шаг 3. Создай отдельный виджет кнопок

Создай файл `lib/widgets/category_filter.dart` и вставь в него весь код:

```dart
import 'package:flutter/material.dart';

import '../models/task_options.dart';

class CategoryFilter extends StatelessWidget {
  final String category;
  final ValueChanged<String> onChange;

  const CategoryFilter({
    super.key,
    required this.category,
    required this.onChange,
  });

  @override
  Widget build(BuildContext context) {
    return Wrap(
      spacing: 8,
      runSpacing: 4,
      children: [
        ChoiceChip(
          label: const Text('Все категории'),
          selected: category == 'Все категории',
          selectedColor: const Color(0xFFE8EFFA),
          onSelected: (value) {
            onChange('Все категории');
          },
        ),
        for (final name in categories)
          ChoiceChip(
            label: Text(name),
            selected: category == name,
            selectedColor: const Color(0xFFE8EFFA),
            onSelected: (value) {
              onChange(name);
            },
          ),
      ],
    );
  }
}
```

### Что делает этот файл

Он устроен почти так же, как существующий `TaskFilter`.

- `category` — текущий выбор, полученный от экрана.
- `onChange` — функция, которой передадим выбранное название.
- `categories` — уже существующий список «Работа», «Учеба», «Планерка», «Дом».
- `ChoiceChip` — кнопка, которая может выглядеть выбранной.
- `selected` — условие для выделения кнопки.
- `Wrap` — размещает кнопки и переносит их на новую строку, если не хватает ширины.

Кнопка «Все категории» описана отдельно, остальные создаются обычным циклом `for`.

`ValueChanged<String>` означает «функция, принимающая строку и ничего не возвращающая». Например, при нажатии «Планерка» виджет вызывает `onChange('Планерка')`.

Параметр `value` обработчика `onSelected` здесь не нужен: мы всегда передаём название кнопки. Повторное нажатие на выбранную кнопку сохраняет выбор. Для сброса категории есть отдельная кнопка «Все категории».

Виджет не хранит свой отдельный выбор и не обращается к списку задач. Его ответственность — кнопки и уведомление экрана о нажатии. Поэтому используется `StatelessWidget`.

## Шаг 4. Подключи кнопки к главному экрану

Открой `lib/todoscreen.dart`.

### 4.1. Добавь импорт

Рядом с импортом `widgets/task_filter.dart` добавь:

```dart
import 'widgets/category_filter.dart';
```

### 4.2. Найди место для нового блока

В `build` найди существующий `TaskFilter(...)`. Сейчас сразу после него стоят `SizedBox(height: 16)` и `DropdownButtonFormField<String>` для сортировки.

Замени участок **от `TaskFilter(` до `const SizedBox(height: 16),` включительно** следующим кодом. Сам `DropdownButtonFormField` и всё после него оставь как есть:

```dart
TaskFilter(
  filter: state.filter,
  onChange: (value) {
    setState(() {
      state.filter = value;
    });
  },
),
const SizedBox(height: 16),
const Text(
  'Категория',
  style: TextStyle(
    color: Color(0xFF163F73),
    fontSize: 16,
    fontWeight: FontWeight.bold,
  ),
),
const SizedBox(height: 8),
CategoryFilter(
  category: state.category,
  onChange: (value) {
    setState(() {
      state.category = value;
    });
  },
),
const SizedBox(height: 16),
```

Этот код должен находиться внутри существующего списка `children` главного `ListView`, на одном уровне с `TaskFilter` и выпадающим списком сортировки.

### Как работает связь

```dart
category: state.category,
```

Экран сообщает виджету текущий выбор, чтобы тот выделил нужную кнопку.

```dart
setState(() {
  state.category = value;
});
```

Нажатие меняет только категорию просмотра. `setState` просит Flutter перестроить экран.

В начале `build` уже есть:

```dart
final list = state.visible;
```

При новом построении getter заново отбирает задачи, теперь с учётом категории. Строку получения списка и код карточек менять не нужно.

Обрати внимание: обработчик категории не присваивает ничего в `state.filter`. Именно поэтому комбинация «Активные» + «Планерка» сохраняется.

## Шаг 5. Проверь результат вручную

После добавления поля состояния выполни горячий перезапуск приложения, чтобы начать с однозначных начальных значений. При запуске через `flutter run` это клавиша `R`. Текущие задачи находятся только в памяти и при таком перезапуске исчезнут.

Создай четыре задачи:

| Название | Категория | Статус |
|---|---|---|
| Подготовить вопросы | Планерка | Активная |
| Обсудить отчёт | Планерка | Выполненная |
| Прочитать конспект | Учеба | Активная |
| Купить продукты | Дом | Выполненная |

Все новые задачи сначала активные. Вторую и четвёртую отметь выполненными кнопкой в карточке.

Перед проверкой очисти поле поиска. Затем пройди сценарии:

| Действие | Ожидаемый результат |
|---|---|
| Все + Все категории | Видны четыре задачи |
| Активные + Планерка | Только «Подготовить вопросы» |
| Выполненные + Планерка | Только «Обсудить отчёт» |
| Все + Планерка | Обе задачи категории «Планерка» |
| Активные + Все категории | «Подготовить вопросы» и «Прочитать конспект» |
| Выполненные + Учеба | «Задачи не найдены» |
| Все + Планерка, поиск «ОТЧ» | Только «Обсудить отчёт» |

Дополнительно проверь:

1. Выбери «Активные» + «Планерка» и выполни видимую задачу. Она должна исчезнуть из этого списка. Переключись на «Выполненные»: она должна появиться там.
2. Выбери «Все» + «Планерка». Измени категорию одной задачи на «Дом». После сохранения задача исчезнет из текущего списка, но будет доступна при выборе «Дом».
3. Переключи сортировку. Она должна менять порядок только тех задач, которые прошли фильтры.
4. При активном фильтре «Планерка» добавь задачу категории «Учеба». Она сохранится, но будет скрыта этим фильтром. Проверь её через «Все категории».
5. Перейди на календарь и вернись. Выбор категории должен сохраниться, потому что `HomeScreen` использует `IndexedStack`.
6. Проверь узкий экран: кнопки должны переноситься, а содержимое — прокручиваться.

Счётчик «Всего задач» продолжит показывать общее число записей. Это ожидаемо: он использует `state.tasks.length`, а не длину отобранного списка.

## Шаг 6. Проверь оформление кода

Из корня проекта выполни:

```powershell
dart format lib/state/todo_state.dart lib/widgets/category_filter.dart lib/todoscreen.dart
flutter analyze
```

Форматирование выровняет отступы. Анализатор поможет найти пропущенные скобки, неверные имена и другие ошибки. Ручные сценарии из предыдущего шага нужны отдельно: анализатор не проверяет, правильно ли совместно работают фильтры.

Новый функционал в рамках этой инструкции не установлен, поэтому эти команды нужно запускать после того, как внесёшь изменения.

## Как проходит действие от кнопки до карточек

```text
Нажатие «Планерка»
  → CategoryFilter вызывает onChange('Планерка')
  → TodoScreen записывает state.category
  → setState запускает перестроение экрана
  → state.visible проверяет поиск, статус и категорию
  → list.sort(compare) сортирует оставшиеся задачи
  → TodoScreen показывает полученный список карточек
```

Хранилище продолжает содержать все задачи. Новый список для экрана содержит ссылки на подходящие объекты. Поэтому существующие редактирование, выполнение и удаление будут работать с теми же задачами и после нового фильтра.

## Частые ошибки

| Ошибка | Что проверить |
|---|---|
| Не найден `CategoryFilter` | Создан ли файл и добавлен ли импорт в `todoscreen.dart` |
| Не найдено поле `category` у `TodoState` | Добавлена ли строка из шага 1 именно в класс `TodoState` |
| Нажатие категории сбрасывает статус | В её обработчике должно меняться только `state.category` |
| Выбор виден, но список не меняется | Есть ли новая проверка в `visible` и вызов `setState` |
| «Все категории» скрывает задачи | Сначала нужно проверить `category != 'Все категории'` |
| Показываются чужие категории | Новая проверка должна стоять до `list.add(task)` |
| Категория пропадает после ввода поиска | Поле выбора должно жить в `TodoState`, а не создаваться заново в `build` |
| Не видна только что добавленная задача | Проверь одновременно поиск, статус и категорию |
| Кнопки выходят за экран | Используй `Wrap`, как в примере, вместо обычного `Row` |

Не используй `repo.tasks.removeWhere(...)` для фильтрации: это удалило бы неподходящие задачи из хранилища. В этой реализации задачи только пропускаются при построении списка для экрана.

Не путай сортировку «По категории» с новым фильтром. Сортировка меняет порядок, фильтр скрывает неподходящие категории. Их можно использовать вместе.

## Самопроверка понимания

Попробуй ответить без кода:

1. Чем `state.category` отличается от `task.category`?
2. Почему «Все категории» не добавляется в `task_options.dart`?
3. Почему новое условие использует `&&`, а не `||`?
4. Почему переключение категории не меняет `state.filter`?
5. Где остаются задачи, которые сейчас не видны?
6. Почему при смене категории задачи она может исчезнуть из списка сразу после редактирования?

Ответы: выбор просмотра и данные одной задачи; это режим просмотра, не категория задачи; пропускаем только при конкретном выборе и несовпадении; фильтры независимы; задачи остаются в `TaskRepo.tasks`; после сохранения заново вычисляется `visible`.
